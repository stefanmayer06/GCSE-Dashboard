# Learning studio — design contract

Mode: Operate for authenticated screens; Read for teaching and sources; Persuade for public entry.
User authorized independent design choices, so no mock-up approval round blocks implementation. Code-led replacement of the old paper-register visual world.

Grounded directions considered: learning field guide, seminar table, annotated atlas, workshop bench, learning studio, library reading room, rehearsal space. Chosen studio combines an open work surface with a narrow contextual rail, a single next action, and a topic evidence map. Digital forms take cues from a well-organized studio: clear working zones, materials close to the current task, and room for drafts.

Seed assignment: candidate 5, 1f836684. Challengers (segment instrument, cracktro queue, roll-supplied alternatives) do not improve learner identification or reading clarity; preserve discipline in stable controls and clear state changes, not visual costumes. No generated raster is needed for this task-focused interface.

First viewport: brand and subject context across top, Today/Learn/Practice/Reflect navigation, one actionable next learning session, adjacent evidence and quick access to due mistakes. No statistics wall. Desktop supports wide reading and context zones; mobile keeps primary destinations at the bottom and account/subject context at the top. Subject text and icons remain explicit.

Signature interaction: topic search and evidence filters reveal a navigable knowledge map; a topic's state is explained in words alongside answer evidence. Accuracy is not mastery. Retry mastery remains the existing notebook evidence model.

Typography: humanist sans for controls and reading, expressive serif only for large learning invitations, tabular numerals for marks/timers. Teal primary action, clay English identifier, plum Foundation identifier; darker themes have dedicated accessible washes and foregrounds. Flat open sections; contained cards only for independent actions. Controls 44px minimum web and 48px native. Focus remains visible; motion optional and under 180ms.

Risk: broad UI replacement must preserve complex subject-specific runners. Integration logic stays intact while shell, discovery, home, reading hierarchy and shared components change.
